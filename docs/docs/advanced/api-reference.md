# API Reference

The backend serves a REST API and an execution WebSocket. All endpoints use the same origin as the app (`http://localhost:8000` by default). The **Auth** column uses the five values defined under [Authentication](#authentication). Each table links to the relevant usage page.

The server also serves FastAPI's generated schema: `GET /openapi.json` (OpenAPI 3.1, every HTTP route on this page; the WebSocket is not in it), `GET /docs` (Swagger UI, with its helper page `/docs/oauth2-redirect`) and `GET /redoc`. All four are open. `/docs` and `/redoc` load their scripts from cdn.jsdelivr.net, so the browser needs internet access to show them; `/openapi.json` does not. When the prebuilt frontend is present, a `GET` for any other path outside `/api/` and `/ws/` returns the file at that path in the frontend build when there is one (the `/assets/...` bundle, `/build-info.json`, and in a release `/LICENSE`, `/NOTICE`, `/THIRD_PARTY_NOTICES.md`, `/COMMERCIAL-LICENSE.md` and `/CONTRIBUTING.md`), else `index.html`. A missing file under `/assets/` and an unmatched path under `/api/` or `/ws/` are 404s, never the editor page.

## Authentication

| Auth | Meaning |
|------|---------|
| open | No credential. Most `GET` / `HEAD` / `OPTIONS` requests use this; the published-app and API-key rows below name the exceptions. |
| token | The `X-CodefyUI-Token` session header. The generic middleware requires it for every `POST` / `PUT` / `PATCH` / `DELETE` under `/api/` except `/api/apps` and `/api/keys`, whose routes enforce one of the policies in this table. It is also the credential for every app-management route (`GET /api/apps` and `GET /api/apps/{slug}/versions` included) and all of `/api/keys`. Missing or wrong: `403 {"detail": "Missing or invalid X-CodefyUI-Token header"}`. Where the token file lives and why it rotates on every restart: [Graph as a Function, section 2](/usage/graph-as-a-function#2-getting-the-token-for-external-scripts). |
| token+loopback | The token, and the server must be bound to a loopback address (`127.0.0.1`, `localhost`, `::1`) — otherwise 403 — unless `CODEFYUI_ALLOW_REMOTE_PACK_INSTALL=1` (packs) or `CODEFYUI_ALLOW_REMOTE_PLUGIN_INSTALL=1` (plugins) was exported first. The gate reads `CODEFYUI_HOST`, never the socket. |
| API key | Only `Authorization: Bearer cdui_...` is accepted. A session token returns an error that states that an API key is required. Authentication failures use status 401 inside the run envelope and include `WWW-Authenticate: Bearer`. Keys are created through `/api/keys`; see [Publish](/usage/publish#2-api-keys). |
| worker token | The long-lived credential a worker agent gets from `POST /api/workers/enroll` in exchange for a one-time enrollment token, sent in the `X-CodefyUI-Token` header (or `?token=`) on `/ws/worker`, and in the header on `POST /api/runs/{run_id}/artifacts/upload` for a run on that worker. Accepted from any peer; it names one worker, whose `hello` must use that name. `DELETE /api/workers/{id}` revokes it. The server stores only its sha256 hash. See [Remote Workers](/usage/remote-workers#adding-a-worker). |
| enrollment token | `abcdef.0123456789abcdef`, generated with `POST /api/workers/enrollments`. Only `POST /api/workers/enroll` takes it, in the JSON body, without a session token; that route is rate-limited per client address (10 attempts, then 10 a minute; `429` with `Retry-After`). |
| key-or-token | Either credential is accepted. These metadata reads are another exception to the general rule that `GET` requests are open. A request with neither credential returns `401 {"detail": "..."}`. |

The Host guard runs before all other checks on every request, including the SPA page and WebSocket. A `Host` header outside the allowlist returns `421 {"detail": "Misdirected Request (Host not allowed)"}`. The allowlist is derived from `CODEFYUI_HOST` and `CODEFYUI_PORT` and extended by `CODEFYUI_EXTRA_ALLOWED_HOSTS`. An SSH worker's tunnel never reaches this port, and no `Host` marks a request as tunnelled: the tunnel lands on a listener the server opens for that worker alone (a Unix socket in a private directory; an ephemeral `127.0.0.1` port on Windows), which serves `/ws/worker` (worker token; the session token is refused there), `POST /api/workers/enroll` (enrollment token) and, with a worker token (`403` without), the transfer backend's input downloads and `POST /api/runs/{run_id}/artifacts/upload`. Every other path there answers `404`, `GET /api/auth/bootstrap` included, whatever the `Host` ([Remote Workers, Connecting over SSH](/usage/remote-workers#connecting-over-ssh)); see [Publish, section 6](/usage/publish#6-serving-on-your-lan) and [Deployment](/usage/deployment). The token middleware exempts `GET /api/auth/bootstrap` so the frontend can obtain the token. Any request with an allowed `Host` can use this endpoint, including a remote client when the server is bound to a LAN address.

## Health and system

| Endpoint | Method | Auth | Description |
|----------|--------|------|-------------|
| `/api/health` | GET | open | Health probe with `status`, `version`, `boot_id` (a process identifier that lets clients detect a server restart), `nodes_loaded`, `presets_loaded`, `caches` (current bytes in each in-memory store and its budget; see [Training Memory](./training-memory)), and `project` (the absolute project directory) when the server runs with `--project`. |
| `/api/auth/bootstrap` | GET | open | `{"token": "..."}` for any allowed-Host request — how the frontend gets the session token. |
| `/api/system/devices` | GET | open | Compute devices for graph execution: the best-available `default` plus a labelled `devices` list that tells NVIDIA CUDA, AMD ROCm and Apple MPS apart. Each device also carries `memory`: `{total_bytes, free_bytes, source}` read at request time (`source` is `nvml`, `torch.cuda`, `torch.mps` or `psutil`), or `null` when nothing could read it. NVIDIA cards are read through NVML (`nvidia-ml-py`), falling back to torch. Backs the editor's device selector, which shows free / total GiB for accelerators. |
| `/api/system/fingerprint` | GET | open | This server's environment fingerprint and its digest: `{fingerprint, digest}`. See [Run environment](#run-environment). |
| `/api/system/fingerprints/{digest}` | GET | open | A fingerprint some run recorded, by its digest; 404 when no run recorded it. Keeps resolving after the runs are deleted. |

## Nodes and presets

| Endpoint | Method | Auth | Description |
|----------|--------|------|-------------|
| `/api/nodes` | GET | open | List all node definitions. Each node carries `details` (its longer description, empty when `description` says it all), `provider` (`builtin`, `custom`, or `plugin:<id>`) and `requires_pack` (the pack the node declares, or `null`), and each SELECT param `option_packs` (option value to pack id). The editor keeps an unavailable current value selectable with a warning, greys out other unavailable options, and offers the install. Neither field stops a run; a node that must not run without its pack refuses in `execute`, as the built-in nodes do (see [Custom Nodes](/advanced/custom-nodes#anatomy-of-a-node)). |
| `/api/nodes/{node_name}` | GET | open | Get a single node definition. |
| `/api/nodes/reload` | POST | token | Re-discover every node and preset source: custom nodes and plugins are re-imported from disk, built-ins are re-registered (not re-imported), presets are re-scanned. Returns `{builtin, custom, plugins, presets, total}`; identical to `POST /api/plugins/reload`. |
| `/api/nodes/script/validate` | POST | token | Check one PythonScript body (`{"code"}`) against the Tier-0 policy while it is being typed: `{ok, error, line, defines_run, allowed_modules}`. `ok: false` is a normal 200, not an error. |
| `/api/presets` | GET | open | List preset definitions. |
| `/api/presets/{name}` | GET | open | Get a single preset definition. |
| `/api/presets/create` | POST | token | Create a new preset from the request's complete `nodes` and `edges`; the editor submits the whole current canvas. |

## Graphs

| Endpoint | Method | Auth | Description |
|----------|--------|------|-------------|
| `/api/graph/validate` | POST | token | Validate a graph: `{valid, errors, issues}`. `errors` lists each problem as an English sentence; `issues` has one `{message, code, node_id, params}` per problem, in the same order: `message` is that sentence, `code` names the check (`null` for a check that has no code yet), `node_id` is the node the problem is about, and `params` are the values the sentence names. The editor uses them to say each problem in the UI language and name the node by its title. |
| `/api/graph/save` | POST | token | Save a graph. The body is the graph plus two optional fields: `file`, the address (filename stem) to write to, and `overwrite`. Omitting `file` means "derive the address from `name`", which is a Save As. Send `overwrite: false` with such a request to opt into the collision guard: one that lands on an address something already occupies then answers `409` with `{"detail": {"error": "graph_exists", "file", "name"}}` instead of writing, where `file` is the stem the server resolved and `name` is the title of the graph already there — re-send with `overwrite: true` to replace it. Leaving `overwrite` out entirely keeps the behaviour this route has always had: the save is written, occupied address or not, so existing clients and scripts are unaffected. A request that carries `file` is saving in place and is never refused this way. The response is `{message, path, file}`: `path` is the file written and `file` is the address the server derived, which later saves, loads and renames use. |
| `/api/graph/load/{name}` | GET | open | Load a saved graph. |
| `/api/graph/list` | GET | open | List saved graphs as `[{name, file, modified}]`: `name` is the title stored in the file, `file` is the address to load, rename or delete it by, and `modified` is the file's modification time in epoch seconds (in a project directory, the `.graph.json` file's, not the layout file's). In a project directory, 409 when a name exists both as `<name>.graph.json` and as a legacy `<name>.json`. |
| `/api/graph/rename` | POST | token | Rename a saved graph: `{"from": "<file>", "to": "<new name>"}`, both non-empty; any other key is 422. Moves the file (and, in a project directory, its `layout/` file) and writes `to` into it as its `name`. Returns `{message, name, file}`, where `file` is the sanitized address to use from then on. 404 when `from` does not exist; 409 when `to` is taken, when a layout file for `to` exists without its graph, or when a name exists in both file forms; 400 when the file is not readable JSON or, in a project directory, when `to` ends in `.graph` or `.layout`. Backs **Rename** in the sidebar's **Graphs** tab ([Tabs & Persistence](/usage/tabs-persistence#saving-and-loading)). |
| `/api/graph/{name}` | DELETE | token | Delete a saved graph, with its layout file in a project directory. Returns `{message, removed}`, the list of deleted paths. 404 when nothing is there; 409 when the name exists in both file forms. Backs **Delete** in the same tab. |
| `/api/graph/export` | POST | token | Export a single-file headless Python runner. It embeds the graph and requires a compatible CodefyUI backend environment, but no running server. The response is `{script, warnings}`, where `warnings` lists the file params whose absolute path ties the script to this computer. |
| `/api/graph/contract/{name}` | GET | open | The saved graph's derived function signature — `inputs`, `outputs`, `problems` — for scripting against it. See [Graph as a Function](/usage/graph-as-a-function#3-inspect-the-contract). |
| `/api/graph/run/{name}` | POST | token | Run the latest saved file as a function: `{inputs, timeout_s, device, record_outputs}` in, the 9-key envelope out on every outcome. See [Graph as a Function](/usage/graph-as-a-function#4-run-the-graph). |
| `/api/examples/list` | GET | open | List the built-in example graphs and those of enabled plugins: `[{name, description, category, path, source, node_count, edge_count, section, family, order}]`. `source` is `builtin` or `plugin:<id>`, `node_count` leaves out notes, and `section`, `family` and `order` place the example in the gallery (see [Examples Gallery, Adding an example](/usage/examples-gallery#adding-an-example)). |
| `/api/examples/load` | GET | open | Load an example graph; `?path=` is a list row's `path`. |

## Runs and sweeps

| Endpoint | Method | Auth | Description |
|----------|--------|------|-------------|
| `/api/runs` | POST | token | Submit a run to the queue and return immediately: `{run_id, status: "running" \| "queued"}`. `options.target` (`{worker, devices}`) names where it executes: `local`, a connected worker, or `any` ([Run Queue, Workers](/usage/run-queue#workers)). A worker name this server has not seen since it started, a worker that does not offer the device, or a degraded worker that lacks a node type the graph uses (the message names the types) is `400`; a known worker that is away queues the run until it reconnects. |
| `/api/runs` | GET | open | Newest-first list; `?status=` repeats, `?limit=` has a maximum of 500, and `?offset=` selects the starting row. Every row includes `queue_position`, `queue_reason` (why a queued run is not starting beyond its place in line, such as `waiting for worker gpu-box to reconnect`, else `null`), `queue_reason_code` and `queue_reason_params` (the same reason as a code and its parameters for a client to word in its own language: `worker_reconnect`, `worker_draining`, `worker_no_mount`, `any_no_worker`, `any_no_worker_mount`, `any_unavailable`, and for memory admission and one-shot workers `memory_wait`, `memory_no_budget`, `one_shot_start`, `one_shot_taken`, `one_shot_run_id`, `one_shot_pool`, `budget_raised` (a raised estimate beside another reason is that reason's `params.raised`); `null` with no reason), `active`, `final_metrics`, `fingerprint_digest`, `execution_facts`, `worker_id` (`local`, a worker's name, or `any` until an `any` run is placed), `devices` (the requested device set or `null`; for a run on a worker, the devices it got), `metric_producers` (`{name: [node ids]}`, `null` for a run-level series), and `worker_status` (for an active run on a worker, `{worker_id, state, disconnected_at, resume_deadline}` with `state` `connected` or `disconnected` and Unix-second times while disconnected; else `null`); `GET /api/runs/{id}` also has `late_result` (`{status, error, worker_id, at}` when a worker reported the run's end after it had ended here, else `null`); the response also includes the unpaged `total`. |
| `/api/runs/{run_id}` | GET | open | Return one run (the same fields as a list row, including `worker_id` and `devices`) and `last_cursor`, which clients use to start event polling, plus `fingerprint`: the environment document its `fingerprint_digest` names (`null` before the run starts). |
| `/api/workers` | GET | open | Every enrolled worker agent and every other agent this server has seen since it started: `{workers: [{id, name, status, draining, same_host, version, fingerprint_digest, platform, mounts, devices[{value, kind, index, name, memory, slots, shared_with}], running, connected_at, last_heartbeat_at, enrolled, credential, plain_http, node_catalog, degraded_reasons}], local, rejections}`. `status` is `online`, `degraded` (a heartbeat is late, or its node catalog differs from this server's; `degraded_reasons` lists `heartbeat` and/or `node_catalog`), `draining` (connected, takes no new runs; `draining` is also a boolean of its own), `disconnected`, or `offline` (enrolled, not connected since the server started; `connected_at` is `null`, and `last_heartbeat_at` is `null` for one never seen); `enrolled` says the worker holds a revocable credential and `credential` how its connection authenticated (`worker_token`, `session_token`, or `null`); `same_host` is `true` for an agent on this machine; `plain_http` is `true` when its connection is plain `ws://` from another machine (the "Plain HTTP" badge: not `wss` as uvicorn reports the scheme, and not a loopback peer such as a same-host agent or an SSH tunnel's local end; see [Remote Workers, Trust](/usage/remote-workers#trust-between-agent-and-control-plane)); `memory` is `{total_bytes, free_bytes, source}` from the latest heartbeat, or `null`; `slots` is `{limit, taken}` for that `(worker, device)` slot, or `null`; `shared_with` is `"local"` when the device is physically one of this server's, whose slot it then shares (count it once), else `null`. `local` lists this server's own devices as `{id: "local", devices[{value, kind, slots}]}`, or is `null` without a run service. `mounts` maps each storage label the worker declared to its path there; a worker on this machine also shows this server's label with this server's path, and `local.mounts` is this server's own label and path ([Storage: shared filesystem](/usage/remote-workers#storage-shared-filesystem)). `fingerprint_digest` is the worker's environment fingerprint digest, resolvable with `GET /api/system/fingerprints/{digest}` (`null` when its last connection reported none). `node_catalog` is `{status, hash, missing, extra}`: `match`, `mismatch` (with the node types this server has and the worker lacks, and the other way round) or `unknown` (the worker reported none) ([Remote Workers, Keeping workers in sync](/usage/remote-workers#keeping-workers-in-sync)). Each worker also has `ssh_enabled` (whether this server's SSH worker of that name is enabled; `null` when it is not one), `memory_budget` (its agent enforces memory budgets), `one_shot` (`{run_id, took}` for a one-shot agent, else `null`) and `instance_of` / `instance` (an instance of a shared credential, else `null`); each of its devices also has `policy` (`exclusive` or `shared`), `admission` (a shared card's ledger, else `null`), `same_card` (the other offerers of the same physical device, `[{worker, device, policy, online, memory_budget}]`) and, in `slots`, `limited_by` (`{worker, device}`) when another offerer's limit applies. `rejections` is each worker name's last refused handshake from an agent that did not get in, newest first, `[{name, reason, at, peer}]` (`at` in epoch seconds, `peer` the client address; kept in memory, cleared when that name connects); a refused attempt to take the name of a connected worker is listed there and never on that worker's card. 503 when the worker registry is not available. |
| `/api/workers/{id}/drain` | POST | token | Stop placing new runs on the worker; runs it is executing continue. Returns the worker entry; 404 for an unknown worker. |
| `/api/workers/{id}/undrain` | POST | token | Place runs on the worker again. Returns the worker entry; 404 for an unknown worker. |
| `/api/workers/{id}` | DELETE | token | Revoke the worker's credential, disconnect it (its running runs end `interrupted`) and forget it; the runs still queued for it fail at once with `worker <id> was removed`. Returns `{id, revoked, failed_runs}`. Its agent is refused from then on. 404 for an unknown worker. |
| `/api/workers/enrollments` | POST | token | A new enrollment token: body `{ttl_s?, uses?, label?, worker?, control_url?}` (`ttl_s` 60 to 604800, default 86400; `uses` 1 to 100, default 1). `worker` makes a re-key token bound to that known worker (404 for an unknown one): the only kind of token that can enroll a name already taken, and it can enroll that name only. Returns `{id, token, expires_at, uses_left, state, label, worker, created_at, control_url, command}`; `command` is `cdui agent start --control <control_url> --token <token>` (plus `--name <worker>` for a re-key token, and `--ca-fingerprint <tls_fingerprint>` over `https` when the server knows the fingerprint), where `control_url` is the body's (an `http(s)://host[:port][/path]` address without shell characters, else `422`) or this request's scheme and `Host`. The token is in this response only. |
| `/api/workers/enrollments` | GET | token | The enrollment tokens, newest first, without their secrets: `{enrollments: [{id, label, worker, created_at, expires_at, uses_left, state}], control_url, other_machine_urls, listening_on_loopback, tls_fingerprint, fingerprint_command}`. `state` is `pending`, `expired` or `used`; expired and used tokens stay listed until deleted. `other_machine_urls` are the allowlisted addresses another machine could dial. `tls_fingerprint` is `sha256:<hex>` of the public key of the first certificate in `CODEFYUI_TLS_CERT_FILE`, or `null` when that is unset or unreadable; `fingerprint_command` is the `openssl` pipeline that computes the same value on the TLS proxy's host. |
| `/api/workers/enrollments/{id}` | DELETE | token | Revoke (or clear away) an enrollment token. 404 for an unknown id. |
| `/api/workers/agent-command` | POST | token | The agent command for an enrollment token at another address, built by the same function as the `command` above: body `{control_url, token, worker?}`, returns `{control_url, command}`. The token is in the body only (never a URL), and is neither checked against the store nor kept. `422` for a malformed address, token or worker name. |
| `/api/workers/enroll` | POST | enrollment token | `{token, name, platform?, devices?, mounts?}` -> `{worker_id, worker_token}`. Spends one use of the token and creates the worker. A name that is already enrolled, or held by a connected same-host agent, is `409` ("worker X is already enrolled; remove it or create a re-key token for it") unless the token is a re-key token for it, which gives it a new credential (the old one stops working and its connection closes). `401` for an unknown, expired or used-up token, with the reason; `403` for a re-key token used for another name; `400` for a bad or reserved name (`local`, `any`, `enroll`, `enrollments`); `429` when rate-limited. A refused enrollment spends no use. Only `POST` on this path skips the session token. Through an SSH worker's tunnel the rate limit is kept per SSH worker rather than per client address. |
| `/api/workers/ssh` | GET | token | The SSH workers this server starts itself ([Remote Workers, Connecting over SSH](/usage/remote-workers#connecting-over-ssh)): `{ssh_workers: [{id, target, port, identity, remote_cdui, remote_port, enabled, state, last_error, exit_code, tail, attempts, retry_at, up_since, gave_up, pid, remote_pid}], ssh_available, port_range, default_remote_cdui}`. `state` is `connecting` (ssh runs, the agent has not connected), `up`, `failed` (ssh exited; `last_error` holds its last lines, `retry_at` the next attempt) or `stopped` (disabled). `remote_port` is the worker's slot from `CODEFYUI_SSH_REMOTE_PORT_RANGE`: its state directory on the remote host is `~/.codefyui-ssh/<id>-<slot>/` (`<id>`: this server's instance id), where the tunnel's Unix socket is. `ssh_available` says whether this machine has an `ssh` on PATH. A GET that needs the session token. |
| `/api/workers/ssh` | POST | token | Add an SSH worker and start it: `{target, port?, identity?, remote_cdui?, name?}`. `target` is `user@host`, `host` or an ssh `Host` alias; `identity` a key file on this machine (it must exist); `remote_cdui` the launcher on the remote host (default `~/CodefyUI/cdui`); `name` defaults to the target's host name. `400` for a value that cannot be used or when `ssh` is missing, `409` for a name an SSH worker or another worker already has. Returns the entry. |
| `/api/workers/ssh/{id}/enable` | POST | token | Undrain the worker and start its ssh session again; on an enabled entry that gave up (`gave_up: true`, forwarding refused), retry it. 404 for an unknown entry. |
| `/api/workers/ssh/{id}/disable` | POST | token | Drain the worker, then end its ssh session: the remote agent stops and a run still on it ends `interrupted`. 404 for an unknown entry. |
| `/api/workers/ssh/{id}` | DELETE | token | Stop the SSH worker and delete its entry; its enrollment stays (`DELETE /api/workers/{id}` revokes it, and removes the SSH entry too). |
| `/api/runs/{run_id}` | DELETE | token | Drop a finished run with its events, metrics, artifact rows and captured outputs; 409 while it is queued or running. Artifact files stay on disk, except what a worker uploaded for the run: its folder here, and its objects in the S3 bucket but `output/` ([An S3 or MinIO bucket](/usage/remote-workers#storage-s3)); when those objects cannot be removed, the answer carries a `warning` saying why. |
| `/api/runs/{run_id}/cancel` | POST | token | Cooperative stop — `{run_id, status, cancelled}`; `cancelled: false` (still 200) for a run that had already finished. |
| `/api/runs/{run_id}/events` | GET | open | Events after `?cursor=`; `?wait=` long-polls for up to 60 s, and `?limit=` accepts up to 2000. Returns `{run_id, status, active, events[{cursor, type, payload, ts}], cursor}`. A page can contain fewer than `limit` events; use the returned `cursor` for the next request. |
| `/api/runs/{run_id}/metrics` | GET | open | Recorded scalar series in `(name, step)` order; `?name=` filters, `?format=csv` downloads (UTF-8 BOM, formula-safe cells). The JSON form also lists `names`. |
| `/api/runs/{run_id}/artifacts` | GET | open | Files the run recorded (checkpoints, exports, images), oldest first; `?kind=` filters, and an unknown kind is an empty list. Each entry is `{id, kind, path, meta, created_at, backend, mount_label, relative_path, worker_id, bucket}`: `path` is where the file is on this server, or `null` for a `mount` row whose mount this server does not hold (then only `mount_label` and `relative_path` name it); `backend` is `local` (an absolute path, every row before mounts existed) `mount` (a file a worker wrote on a shared mount, stored as `relative_path` under `mount_label` and translated to this server's path) `transfer` (a file a worker without the mount uploaded here, stored at `relative_path` under this server's data folder) or `s3` (a file a worker without the mount uploaded to the S3 bucket, `path` being `s3://<bucket>/<key>`, `relative_path` the object key and `bucket` the bucket); `worker_id` is the worker whose run wrote it (`local`: this server); `bucket` is `null` on every row but `s3`, and `mount_label` on every row but `mount`. |
| `/api/runs/{run_id}/artifacts/upload` | POST | worker token | A worker's output for a run executing on it ([Storage: no shared filesystem](/usage/remote-workers#storage-no-shared-filesystem)). Multipart, form fields first: `kind`, `name` (a relative path), `place` (`run`, the default, or `data`) and optional `sha256` (checked), then `file`; the body is streamed to disk. `run` stores at `<data folder>/runs/<run_id>/<kind>/<name>`; `data` (a writer node's file, `name` under `models/`, `media/` or `output/`) stores at that relative path in this server's data folders, never over a different file (the newer one gets a `-1`, `-2` ... suffix). The same content again answers 200 with the same key. Answers `{path, bytes, sha256}`, `path` being the key the worker then reports. The session token may upload for any worker run; a worker token only for a run on that worker (`409` otherwise, and when the run is not executing on a worker); `403` without either. Capped by `CODEFYUI_MAX_UPLOAD_SIZE` (`413`). |
| `/api/runs/{run_id}/artifacts/{artifact_id}/download` | GET | open | The file of a `transfer` row (in the run's folder, or a writer's file in the data folders), as an attachment. The object of an `s3` row ([An S3 or MinIO bucket](/usage/remote-workers#storage-s3)), streamed from the bucket, or with `CODEFYUI_S3_DOWNLOAD=presign` a `307` to a pre-signed URL; `503` when the bucket cannot be reached. `400` for any other row (its file is at its `path`) and for a directory (a TensorBoard folder); `404` when the row or its file is gone. |

**Runs API.** `POST /api/runs` accepts `{"graph": {...}, "options": {...}, "name": "..."}`. The graph uses the saved-graph JSON format (`nodes`, `edges`, and optional `presets`, `subgraphs` and `settings`). The endpoint returns 422 when the body is not JSON or has no `graph` object, 400 for an invalid graph (for example empty `nodes` or a bad `settings.device`) or option, and 503 when the run service is unavailable or an `interactive`-lane submission exceeds the limit. Option keys are a closed set: `device`, `seed`, `deterministic`, `record_outputs`, `lane`, the canvas flags `verbose`, `graph_id`, `weights_persistent`, `backward_mode`, `auto_backward`, the engine error policy `error_mode`, `max_retries`, and `target`. The run's device is the first entry of `options.target.devices` when given, else `options.device` when given, else the graph's `settings.device` (see [the graph settings object](/advanced/device-backends#the-graph-settings-object)), else `cpu`. `target` is `{"worker", "devices"}`: `worker` is `local` (the default), the name of a connected worker agent, or `any`, and `devices` is a set of concrete devices of one kind. A worker name that has not connected since the server started, a worker that does not offer the devices, an `any` run that neither this server nor a worker it has seen could serve, a worker target combined with the interactive lane, and `record_outputs` on a named worker whose agent does not support it are 400; a known worker that is away queues the run until it reconnects. On this server a set run holds a slot on every device and executes on the first; on a worker it uses them all (see [Run Queue, Workers](/usage/run-queue#workers) and [Execution Architecture](./execution-architecture#scheduling)). A run's `status` is one of `queued`, `running`, `succeeded`, `failed`, `cancelled`, or `interrupted`. Two limits apply to `/events`: a payload over `CODEFYUI_RUN_EVENT_PAYLOAD_CAP_BYTES` (128 KB) is stored with its outputs replaced by an elision marker, and a response ends once it exceeds `CODEFYUI_RUN_EVENTS_RESPONSE_CAP_BYTES` (4 MB). See [Run Queue](/usage/run-queue) for queue order, lanes, retention, and `cdui run`.

**Sweeps.** `POST /api/sweeps` accepts `base_graph`, a `sweep_spec` (`method` `grid` or `random`, `seed`, `samples`, and `params[{node_id, param, values | range}]`), a required `objective` (`metric`, `direction` `minimize` or `maximize`, and an optional `node_id` naming the node whose series ranks the sweep), the same `options`, a `name`, and `seed_variants`. It creates at most `CODEFYUI_MAX_SWEEP_RUNS` (32) variants. Each variant is an ordinary `/api/runs` row whose `/events` endpoint can be followed separately. See [Run Queue — Sweeps](/usage/run-queue#sweeps) for the specification, validation errors, and cancellation behavior.

**Studies.** `POST /api/studies` accepts `name`, a required `objective` (`node_id`, `metric` and `direction`, all three required), `base_graph`, `variants[{label, graph | ops[{node_id, param, value}]}]`, `repetitions` (1 to 32), `seed`, `options` (as for a sweep, without `seed` or the interactive lane), `budget` (`max_runs`, `max_parallel_runs`, `max_run_seconds`, `max_active_seconds`), `resume_policy` (`explicit` or `auto`) and `idempotency_key` (a key starting with `plugin:` is refused: that prefix scopes [plugin jobs](#plugin-jobs)). A study's `status` is one of `queued`, `running`, `cancel_requested`, `succeeded`, `failed`, `cancelled`, `interrupted` or `halted` (a budget ran out); an attempt's is `pending`, `submitting`, `queued`, `running`, `succeeded`, `failed`, `cancelled`, `interrupted`, `lost` or `timed_out` (stopped for `max_run_seconds`). The budgets are enforced by the server; see [Studies, Budgets](/usage/studies#budgets). Only variants whose scheduled repetitions all succeeded and recorded the objective are ranked. A sweep table ranks a failed run on the value it logged; in a study, that run makes its variant ineligible. Each child is an ordinary `/api/runs` row carrying `study_id` and `study_attempt_id`. See [Run Queue — Studies](/usage/run-queue#studies) for seeds, ranking, cancel, resume and the restart policy.

### Run environment

A run records two things about how it was submitted, and since #344 two about where it executed.

- **At submission:** `options` (device, seed, determinism and the rest, after the graph's `settings` fill in what the request left out), and `git_commit`, `git_dirty` and `plugin_pins` (the user's project commit and the enabled plugins in the lockfile). These describe the request and the project, not the CodefyUI code that runs it.
- **At execution start:** `fingerprint_digest` and `execution_facts`, written when the run leaves the queue and begins. A queued run that waited through a server update therefore records the environment that actually executed it, while its submission fields still say what they said. For a run on a worker, `fingerprint_digest` is the worker's environment as its agent reported it when it connected ([#781](https://github.com/CodefyUI/CodefyUI/issues/781)), and `execution_facts.worker_id` names the worker.

`GET /api/system/fingerprint` returns the fingerprint document for the server as it is now, with `schema_version` 1. Every key is present in every document, and a fact that cannot be read is `null`:

| Key | Contents |
| --- | --- |
| `codefyui` | `version`, `commit`, `dirty` and `commit_source`: `git` when the server runs from a checkout, `build-info` when only `frontend/dist/build-info.json` names a commit, else `null`. Read once per server process, because the code that runs is the code that was loaded at startup. |
| `python`, `platform` | Python version and implementation; operating system, kernel release, machine and macOS version. |
| `libraries`, `torch_build` | Installed `torch`, `torchvision`, `numpy` and `mlx` versions; torch's build commit, CUDA, HIP and cuDNN versions. |
| `accelerators`, `devices` | CUDA, ROCm, MPS and MLX availability, each CUDA card's name and compute capability, the NVIDIA driver version when `pynvml` can read it; the server's default device and the devices it offers. |
| `plugins` | Each enabled pack: `source_kind`, `source`, `ref`, `version`, `revision` and `revision_kind`. A pack installed from a repository has its commit (`git-sha`). A builtin pack ships inside the checkout, so its revision is the CodefyUI commit (`codefyui-commit`) and its source is `plugins/<id>`. A linked local pack has no immutable revision, so both are `null` and its path is withheld. |
| `custom_nodes`, `optional_packages` | The sha256 of each enabled custom node file; the installed version of each Package Center pip distribution (`null` when not installed). |
| `env` | The values of a fixed list of variables that change numerics or device selection, such as `CUBLAS_WORKSPACE_CONFIG`, `CUDA_VISIBLE_DEVICES` and `ONEDNN_MAX_CPU_ISA`. No other environment variable is read. |

The document carries no hostname, username, home-directory path or secret. The `digest` is the sha256 of the document's canonical JSON (sorted keys, no whitespace, UTF-8) and covers every key, so the same environment gives the same digest and a change to any recorded fact gives a different one. Each distinct document is stored once; retention and `DELETE /api/runs/{run_id}` leave it in place, so `/api/system/fingerprints/{digest}` still resolves a digest after its runs are gone.

`execution_facts` sets the request next to what the run got. `requested` holds `device`, `seed` and `deterministic` from the stored options, plus `graph_settings_device` and `graph_settings_seed` from the graph. `resolved` holds the device the scheduler resolved (`auto` becomes, for example, `mps:0`), the seed and determinism flag handed to the engine, and `numerics`: torch's default dtype, float32 matmul precision, TF32 and cuDNN benchmark switches, and thread count when the run started. There is no run-level precision option; mixed precision is a parameter of the training nodes and is recorded in the graph snapshot. A node with its own `device` parameter can override the run's device for that node.

When a run that executed finishes, `execution_facts` also gets `peak_memory`, whatever the outcome. A CUDA run records one entry per card the server process holds memory on, the run's own card first, so a node pinned to another card is counted too: `{"cuda:0": {"allocated_bytes": N, "reserved_bytes": M, "exact": false}}`, the allocator's high-water marks (`max_memory_allocated`, `max_memory_reserved`) over the run. An MPS run records `{"mps": {"held_bytes": N, "exact": false}}`: what the Metal driver holds for the server process when the run ends, its cache included. MPS has no peak counter, so this is not a peak. A CPU run is measured the same way, so a node that pinned a CUDA card puts that card in the map. A run with no card in use (a plain CPU run), or in a server where torch is not loaded or CUDA was never initialised, records `null`. Reserved memory with no allocation during the run is not counted on a card whose counters the run reset, because there it is cache an earlier run left behind. A run that stopped before it executed, or whose executor failed without reporting, records nothing (the key is absent). `exact` is `false` for every run that executes inside the server process, because those runs share one CUDA context. A run on a worker executes in a child process that holds that run alone, so its CUDA entries are `exact: true` and never `shared`; the MPS figure stays `exact: false` everywhere because it includes the driver's cache. The peak counters belong to the process, so a run resets them at its start only when no other in-process run is on that card. Otherwise it leaves them alone, so it does not wipe the other run's peak, and marks the card `"shared": true`: the number then also covers the other run. The Runs panel's detail header shows the largest CUDA value as "Peak memory", or the MPS value as "Memory held at end", with every device listed on hover.

A matching digest and seed do not guarantee identical numbers. Nondeterministic kernels and thread scheduling can still change results, and the same seed on different hardware or library versions can produce different values. The digest tells you whether the two environments are the same.

## Plugin jobs

A plugin can hand durable work to the server under its own id, following the Graph Copilot plugin's backend agent contract (#343). The job keeps running after the tab closes. The model conversation and the approval stay in the plugin's page; the server runs no model.

| `/api/git/pull` | POST | token | `{strategy?: "ff-only" \| "merge"}` (default `ff-only`): fetch, then merge the upstream. A diverged branch under `ff-only` is 409 `diverged`; a merge that conflicts is 409 `conflict` and stays in progress. |
| `/api/git/push` | POST | token | `{remote?, set_upstream?: false}`. `set_upstream: true` publishes the branch (`push -u`) to `remote`; when `remote` is omitted, to the branch's upstream remote if it has one, else to the only remote (400 `invalid_value` with several, 409 `no_remote` with none). `remote` without `set_upstream: true` is 400. | `/api/git/sync` | POST | token | Pull (fast-forward only) and then push, or publish a branch whose upstream is missing or gone. No body. It stops at the first failure, and the steps before it stay done; `detail.steps` lists the steps that ran. |

- **Responses.** Every write except `PUT /api/git/config` answers `{status, changed_paths, head, detail}`: a fresh status, the files the operation changed, HEAD afterwards, and operation-specific extras.
- **Errors.** A failure is `{"detail": {"code", "message", "hint", "stderr"}}`. `code` comes from a fixed list that the editor translates, and `stderr` is the tail of git's own output; `message`, `hint` and `stderr` are redacted of anything that looks like a credential. `busy` (409) also carries `op`, the operation that holds the lock. 503 `git_service_unavailable` means the server's startup did not create the git service.
- **Repository state.** Every route other than `status` and `init` needs `repo.state` to be `ready`, and otherwise fails with that state as its code: `no_project` (409; the server was started without `--project`), `git_missing` (503), `git_too_old` (409) or `not_repo` (409). `init` needs only the project directory and git 2.23 or newer.
- **One operation at a time.** A second write while one runs is 409 `busy`. `fetch`, `push` and the network steps of `pull` and `sync` hold a separate lock, so a commit still works while a push is transferring, and a second network request is the one that gets 409 `busy`.
- **Dotenv files.** `/diff` and `/file` refuse `.env` and `.env.*` (not `.env.example`; matched case-insensitively) in any path segment, at every ref, with 403 `ignored`.

## Limits and errors

- **Body size.** `MAX_RUN_BODY_BYTES` (64 MB, `CODEFYUI_MAX_RUN_BODY_BYTES`) limits every request body and counts bytes as they arrive, including chunked requests. Four routes use `MAX_UPLOAD_SIZE` (500 MB, `CODEFYUI_MAX_UPLOAD_SIZE`) instead: `/api/files/upload`, `/api/images/upload`, `/api/models/upload`, and `/api/custom-nodes/upload`. They allow an additional 64 KB for multipart metadata and apply the configured limit to the file itself. Exceeding either limit returns 413.
- **File names.** The four upload routes store a file under the part of its name after the last `/`, and answer 400 for a name that Windows cannot store: one that contains `< > : " \ | ? *` or a control character, is longer than 255 bytes in UTF-8 (a Chinese character takes 3), is made only of dots, or is a device name such as `con.csv`. The rule is the same on every server OS, so uploaded files can move between Windows, macOS and Linux. The download and delete routes and `/api/custom-nodes/toggle` refuse a name with a control character, and on a Windows server also one with those characters; on Linux and macOS such a name is looked up as usual, so a file already stored under one stays reachable. They set no length limit: a name part longer than the server's file system holds answers 404. `/api/custom-nodes/upload` and `/api/custom-nodes/toggle` also refuse names that start with `__`, such as `__init__.py`. Each refusal's `detail` says what to change. `/api/presets/create` applies the same rule to a preset's name, measuring the length of the file it writes (the name with `.json` added), with a coded `detail`.
- **Order of refusals.** The Host guard runs first and can return 421, authentication runs next and can return 403 or 401, and body-size validation runs last. A rejected request body is not read. An unauthenticated request therefore does not receive a 413 response.
- **WebSocket frames.** `WS_MAX_MESSAGE_BYTES` (`CODEFYUI_WS_MAX_MESSAGE_BYTES`, which defaults to the request-body limit) is enforced by the transport. An oversized frame closes the connection with code 1009 rather than returning 413. See [Graph as a Function, section 8](/usage/graph-as-a-function#8-limits-and-gotchas) when launching uvicorn directly.
- **Error shapes.** The API uses four formats by route family:
  1. `{"detail": "<text>"}` — the default format, including 413 responses and the 403 that the loopback gate returns on plugin and pack routes. Pack routes add fields next to `detail`, such as `job_id`, `reason`, `blocked_by`, `command`, `needed`, and `free`.
  2. `{"detail": {"code", "message", "details"}}` — app-management routes and `/api/keys`, for example 404 `app_not_found`, 422 `incomplete_cursor`, and 404 `key_not_found`.
  3. `{"detail": {"code", ...}}` without `message` — Plugin Center routes. Additional fields can include `job_id`, `known`, `missing_capabilities`, `allowed_modules`, `plugin_id`, `inspection_id`, and `id`.
  4. `{"detail": {"code", "message", "hint", "stderr"}}` — every `/api/git` failure; `busy` also carries `op`. See [Source control](#source-control).

  Two shapes cut across the families: the `/api/graph/save` collision guard answers 409 `{"detail": {"error": "graph_exists", "file", "name"}}`, and a request that does not match a route's declared body or query parameters (a missing field, an unknown key where the body forbids one, a value out of range) is FastAPI's 422 `{"detail": [{"type", "loc", "msg", ...}]}`.

  `POST /api/graph/run/{name}` and `POST /api/apps/{slug}/invoke` are the exception to all of these: every response — 413 and 401 included — is the 9-key run envelope, see [the envelope](/usage/graph-as-a-function#the-response-envelope).

## WebSocket protocol

| Endpoint | Method | Auth | Description |
|----------|--------|------|-------------|
| `/ws/execution` | WebSocket | token | Attach/subscribe view over a run: `execute` starts one, `attach` replays its event log from a cursor and then follows it live, `detach` unsubscribes, `cancel` stops it. Closing the socket never cancels. |
| `/ws/worker` | WebSocket | worker token, or token from loopback | Where worker agents (`cdui agent start`) connect. The credential travels in `X-CodefyUI-Token` (or `?token=`): a worker token is accepted from any peer, the session token only from a loopback peer. A `Host` outside the allowlist, or any request carrying an `Origin` header, is closed with **4003** before the socket is accepted (an HTTP client sees `403`), and a missing or invalid credential is answered with HTTP **401** (under uvicorn; a server without handshake responses closes with **4401**, which also reads as `403`). Only a `401` tells the agent that its token was refused. The first frame must be `hello` within 10 s; a protocol-version or CodefyUI-version mismatch (both ends must run the same release), an invalid or reserved worker name, a worker token's `hello` under another worker's name, or a connection replacing a live one of the same name that authenticated another way gets `reject` and a close. A worker counts as on this machine only when it connects from loopback and reports this machine's id. The frames are defined in `backend/app/core/worker_protocol.py`; see [Execution Architecture](./execution-architecture#event-path). When it closes, the worker's runs keep running there and become `disconnected`; they continue when the worker reconnects within `CODEFYUI_WORKER_RESUME_GRACE_S` (300 s) and end `interrupted` after that, at once with a grace of `0` or when the worker is removed ([Remote Workers, When the connection drops](/usage/remote-workers#when-the-connection-drops)). |

**Handshake.** `ws://<host>:<port>/ws/execution?token=<session token>` — the `?token=` query parameter, since browsers cannot set headers on a WebSocket handshake, or the `X-CodefyUI-Token` header for non-browser clients. Close codes before the socket is accepted: **4003** when the `Host` — or, for a browser, the `Origin` — is not whitelisted, **4401** for a missing or invalid token; **1009** later, for a frame over the size cap.

**Client actions** — JSON text frames with an `action` field:

| Action | Fields | Effect |
|--------|--------|--------|
| `execute` | `nodes`, `edges`, `presets`, `subgraphs`, `settings`, `device`, `seed`, `deterministic`, `record_outputs`, `changed_nodes`, `name`, and the canvas flags (`verbose_mode`, `graph_id`, `weights_persistent`, `backward_mode`, `auto_backward`, `error_mode`, `max_retries`) | Submit on the interactive lane and attach to the new run. A run this socket already follows is detached, not cancelled. `settings`, the graph's own settings object, is stored with the run's graph; the run itself uses `device`, which is `cpu` when omitted. The run is listed under `name` (the canvas sends its tab's label), clipped to 64 characters. |
| `attach` | `run_id`, `cursor` (an integer, 0 or more, not past the run's latest cursor) | Replay the event log from `cursor`, then follow live; replaces the previous attachment. |
| `detach` | — | Stop following. Never cancels. |
| `cancel` | `run_id` (optional; defaults to the attached run) | Cooperative stop. The pre-v2 alias `stop` was removed in 3.0. |
| `clear_cache` | — | Drop this socket's execution cache. |

**Server frames.** Stored run events use `{type, run_id, cursor, ...payload}` (`execution_start`, `node_status`, `execution_stopped`, and others). A `node_status` for a block or preset card rolls up every node inside it. Those nodes report on `inner_node_status {node_id, container_id, status}`, plus `error` and `error_type` on an error and `outputs` when the node produced something (its media entries and port summary; its text stays on the card's frames), where `node_id` is the id the run gives the node (`<instance>/<node>`, deeper for nested blocks) and `container_id` is the outermost card. A card's terminal `node_status` carries a port summary of its exposed outputs. A progress frame from inside a card stays a `node_status` for the card and names the node in `inner_node_id`. A node the run bypassed is reported once, before anything runs, with status `bypassed`, and a node left out because a Switch's `selector` param does not pick its branch is reported the same way with status `unselected`. Clients use `cursor` when attaching again. Transport-only frames are `attached {run_id, cursor, status}`, `detached {run_id}`, `cancel_ack {run_id, status, cancelled}`, `execution_stopped {reason: "not_running"}` when no run can be cancelled, `cache_cleared`, `error {error}` for a malformed or unknown action, and `execution_error {error}` when the run service rejects a submission. `cancel_ack` acknowledges the request; the run emits its own `execution_stopped` event after it stops. Rejections caused by the interactive limit or the one-run-per-session rule also include `rejected: true` and the currently attached `run_id`. In that case no new run starts, and the existing attachment remains active.
