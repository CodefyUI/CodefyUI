# 子圖

**子圖**是把一整塊圖收合成單一節點。和預設模組不同——預設模組在你拖進來的當下就被攤平一次——子圖保留一份活的定義：同一個子圖的每個實例都指向同一塊內容，所以改定義就等於同時改到所有用到它的地方。

子圖是**屬於單一圖檔的**。定義會跟著圖檔自己的 `subgraphs` 清單一起走，所以存檔或匯出的圖仍然是一個可以整包帶走的檔案，不需要另外安裝任何東西。

## 把選取收合起來

1. 選取兩個以上的節點（Shift+點擊，或拖一個框把它們框起來）。
2. 在其中一個節點上按右鍵，選**收合成子圖**。
3. 幫這個方塊取個名字。預設是 `Subgraph`，之後也可以從上方的路徑列改名。

選取的節點會被換成一個實例節點。每一條跨越選取範圍的連線都會變成那個節點上的一個**邊界連接埠**，名字取自它所代表的內部連接埠。從**起始節點**來的觸發連線也會被記住：一條進入方塊的觸發連線，展開時會再分送回原本被觸發的那些節點。

收合和展開各自都是**一次復原**——按一次 Ctrl+Z 就會把圖完全還原，連定義一起。

### 什麼情況下會拒絕收合

寧可拒絕，也不要畫出一張讀起來是錯的圖：

| 拒絕的情況 | 原因 |
| --- | --- |
| 只選了一個節點 | 一個節點的方塊就是那個節點本身。 |
| 選到**起始節點** | 起始節點標示的是整張圖從哪裡開始。放進可重用的方塊裡，會變成每個實例各自帶一個起點。 |
| 選到註記 | 註記是說明，不參與計算。 |
| 夾在兩個選取節點中間的節點沒被選到 | 這樣方塊會同時餵給那個節點、又被它餵回來——畫面上看起來是一個迴圈，但攤平後的圖其實沒有。錯誤訊息會告訴你要補選哪些節點。 |

## 編輯方塊

**雙擊**實例節點就會在畫布上打開它的定義。上方會出現一列路徑——`主圖 ▸ 我的方塊`——而你已經熟悉的操作全都照舊：拖曳、連線、刪除、改參數、復原。

在方塊裡按復原只會影響方塊裡面：你在裡面的時候，方塊有自己的一份紀錄；離開時外層的紀錄會被放回來，所以你不會不小心一路復原到方塊外面去。

**離開方塊本身就是一次復原。**你在裡面做的所有修改會合併成外層紀錄上的一筆，所以出來之後按一次 Ctrl+Z，就會把這趟進去做的事整個還原，而且不會動到你在方塊**外面**做的任何修改。進去看一看、什麼都沒改就出來，則完全不會留下復原紀錄。

點路徑上的方塊名稱可以改名（以唯讀方式開啟的圖不會提供改名），按**返回**離開一層，按**主圖**直接回到最外層。

在方塊裡刪掉一個節點，它提供的那個邊界連接埠也會一起消失，外面指向那個連接埠的連線也會跟著移除。

## 兩個實例，一份定義

複製一個實例節點，或是把同一塊內容收合兩次，兩個節點都會指向同一份定義。從任何一邊去改，兩邊都會變——這就是攤平式預設模組做不到的重用。

把一個方塊的最後一個實例刪掉之後，它的定義就不會再被存進圖檔，所以檔案裡不會留著畫布上找不到的方塊。按復原兩者都會回來。

:::note 第一版不支援個別實例的參數
同一個子圖的兩個實例是**完全一樣的方塊**。你沒辦法讓其中一個實例用不同的學習率；如果需要這樣做，請把那個參數留在方塊外面再接進去。個別實例覆寫是後續才會做的事。
:::

## 執行含子圖的圖

不需要任何額外設定。執行前伺服器會把每個實例**內聯展開**，做法和它本來展開預設模組的方式完全一樣，所以收合後的圖執行結果和收合前一模一樣。收合、執行、展開、再執行：數字都相同。

執行過程中，實例節點會顯示一個彙總後的狀態——裡面第一個節點開始時顯示執行中，最後一個節點結束時顯示完成；只要裡面任何一個節點失敗或提早停止，就立刻顯示錯誤或中斷。

執行時內部節點會有**加上命名空間的識別碼**，`<實例>/<節點>`，這也是你在教學檢視器和驗證訊息裡會看到的形式。

### 跨越邊界的驗證

因為驗證同樣會先展開實例，所以它會檢查方塊的內部：跨邊界的連接埠型別、沒接上的必要輸入，以及那個你在畫布上看不到的——**定義內部的環**。這類問題回報時會給出一條同時點名兩邊的路徑：

```
Graph contains a cycle: blk1/relu -> blk1/conv -> blk1/relu
  (crosses subgraph instance(s): blk1)
```

每一層外包的方塊都會被點名，所以往下兩層才出現的環，會同時指出你看得到的那個方塊和它裡面的那一個（`crosses subgraph instance(s): blk1, blk1/inner`）。

如果一個子圖直接或間接包含了自己，執行前就會被點名拒絕。

巢狀最多 10 層，和預設模組的巢狀上限相同。

## 東西存在哪裡

在[專案資料夾](../usage/project-directories.md)模式下，切分方式和最外層的規則一致：

- `graphs/<名稱>.graph.json`——定義本身：節點、連線與介面。
- `layout/<名稱>.layout.json`——`subgraphPositions`，也就是每個方塊裡各節點的位置。

所以改接線會出現在程式碼審查的差異裡，在方塊裡拖曳則不會。

## 匯出成 Python

`匯出 → Python` 會為**每個子圖實例產生一個函式**：

```python
# ========================== Subgraph functions ==========================


def subgraph_myblock(ctx, results, provided):
    "subgraph 'myblock' - instance 'blk1'."
    # ScalarMultiply -> Print
    results['blk1/mul'] = n03_scalarmultiply(
        ctx,
        tensor=_port(results['src'], 'tensor'),
    )
    results['blk1/p'] = n04_print(
        ctx,
        value=_port(results['blk1/mul'], 'tensor'),
    )


# ============================ Flow functions ============================


def flow_1(ctx, results, provided):
    'Start -> TensorCreate -> ScalarMultiply -> Print'
    start = results['start'] = n01_start(ctx)
    src = results['src'] = n02_tensorcreate(ctx)
    subgraph_myblock(ctx, results, provided)
```

方塊的結構會被保留到匯出的檔案裡，而不是被打散成一長串節點呼叫。每個產生的節點函式也會附上一行註解，說明它來自哪個子圖。

有一種例外，而且匯出的檔案會直接寫出來：一個方塊要能變成單一函式，前提是它裡面的節點可以連續跑完。如果中間必須先跑方塊外面的東西——可能是你把方塊接到某個節點、那個節點又接回方塊，也可能是方塊裡有個節點本身沒有任何輸入——匯出就會改成照真正的執行順序把這些節點展開排好，並且用註解說明是什麼卡在中間。腳本照樣可以跑，算出來的結果也和畫布一致，只是少了那個額外的函式。

## 第一版的限制

- 不支援個別實例的參數覆寫（見上方說明）。
- 子圖只屬於單一張圖，目前還沒有共用的子圖庫。
- 放在子圖裡的 `GraphInput` / `GraphOutput` 節點不會被算進這張圖對外公開的 API 合約（把圖當成函式呼叫時用的那組輸入輸出）——請把它們留在最外層。
- 略過（bypass）不適用於實例節點，原因和預設模組一樣：略過是在節點類別宣告的連接埠之間傳遞值，而邊界連接埠沒有這樣的宣告。
- `匯出 → 匯出為子圖`（做出來的是**預設模組**，不是方塊——這兩個功能在中文和英文裡剛好都共用「子圖」這個詞）會拒絕含有收合方塊的畫布，並且把它們的名字列出來。預設模組在伺服器端只存節點和連線，沒有地方可以放子圖定義；用這種畫布做出來的預設模組會帶著一個 `subgraph:<id>` 節點，而它的定義永遠跟不過去——任何人拿去用都是壞的，而且是永久性的，因為預設模組活得比它出身的那張圖還久。請先把方塊展開（在方塊上按右鍵 → 展開）再匯出。
