# 執行圖

當你點擊 **執行** 時，前端會透過 WebSocket（`ws://host/ws/execution`）把圖送到後端，後端則在每個節點完成時把結果串流回來。

## 即時執行

- 後端會驗證圖（DAG 檢查、型別安全、至少一個 [`Start`](./first-graph) 節點），對它進行拓撲排序（Kahn 演算法，含循環偵測），並平行執行彼此獨立的節點。
- 每個節點在執行過程中回報狀態：`running` → `completed`（或 `error`），並內嵌一份精簡的 **輸出摘要** 方便快速查看。
- **執行紀錄** 分頁會顯示這種逐節點的進度，以及任何 `Print` 節點的輸出。

## 沒有 trigger 的節點仍然可能執行

單純移除一個節點的 trigger 邊，並不會讓它退出這次執行。只要還有一條 **data** 邊把它的輸出接到某個確實會執行的節點——不論接的是必要輸入還是選用輸入，都一樣——這個節點就會跟著執行，不管它自己有沒有 trigger。`Dataset` 或轉換鏈的第一個節點，本來就通常沒有 trigger，也本來就預期要這樣執行；同樣的規則也適用於任何你已經接上線的其他節點。

實際的影響是：**光是拔掉 trigger 邊，已經沒辦法讓一段分支停下來了。** 如果你想讓某個節點保留接線、留到之後再用，但現在不要執行，請改成拔掉它的 **data** 邊——那才是真正會讓它退出這次執行的做法。**略過**（右鍵點節點，或按 `Ctrl`／`Cmd`+`B`）是鏈中間節點的一鍵替代方案：跳過該節點本身，直接把輸入原封不動傳給它原本要餵的對象——但這只有在該節點有一個輸入的型別跟它的輸出相同、可以拿來轉發時才有效，所以對完全沒有輸入的來源節點（`CSVReader`、`ImageReader`、`Dataset`，以及其他檔案讀取節點）會被拒絕。對這類節點，拔掉連線是唯一能讓它停下來的辦法。

有一個後果值得知道：一個讀取節點（`CSVReader`、`ImageReader` 之類）就算只是接到某個輸入埠——即使是選用輸入埠——只要沒有 trigger，過去會被悄悄跳過，現在則會執行。如果它指向的檔案後來被刪除或搬走了，一張原本執行都不會出錯的圖，現在可能會在這個節點上開始出現 `FileNotFoundError`。

## 訓練迴圈與 loss 圖表

`TrainingLoop` 節點會在訓練期間發出進度事件。結果面板的 **訓練** 分頁會在每個 epoch 完成時繪製 **即時 loss 圖表**，讓你即時觀察收斂情況。

## 部分重新執行（髒節點追蹤）

CodefyUI 會追蹤哪些節點是 **髒的（dirty）**。當你變更一個節點的參數或輸入時，只有該節點及其 **下游依賴** 會被標記為需要重新執行。未變更的節點則回傳快取的輸出（顯示為 `cached`），因此在單一超參數上反覆調整時，只會重新執行圖中受影響的部分 — 在開發過程中大幅加速。

確定性的節點會自動快取；非確定性的節點（訓練迴圈、隨機運算，或任何 `cacheable = False` 的節點）則一律重新執行。

### 檔案讀取節點的內容感知快取

快取項目的鍵是節點類型、參數、上游節點的快取鍵，加上執行裝置的雜湊組合而成。任何節點從圖之外讀取的東西，光靠 `params` 是看不見的——`path` 參數記錄的是「要去哪裡讀」，不是「那裡有什麼」。因此，會讀取外部狀態的節點也會把內容指紋摺進它的鍵裡：解析後檔案的大小與修改時間，加上（8 MB 以下的檔案）一份內容雜湊，這樣一來，就算是落在同一個檔案系統時間戳記刻度內、大小相同的修改，也還是會讓鍵改變。`CSVReader`、`FileReader`、`ImageReader`、`ImageBatchReader`、`Dataset` 和 `ImageFolderDataset` 都是這樣運作——編輯檔案（或者，對 `Dataset`／`ImageFolderDataset` 而言，編輯這個資料集自己的檔案）之後再按 **執行**，會拿到新的內容；不去動它，則會拿到快取結果而不是重新讀取一次。

`Dataset` 只會對自己這個資料集所在的目錄取指紋——MNIST 是 `MNIST/`、CIFAR-10 是 `cifar-10-batches-py/`，依此類推——而不是整個 `data_dir`。這件事有影響，是因為在專案目錄底下每個資料集都共用同一個 `assets/data/`，而且 `assets/models/` 就在旁邊：在縮小範圍之前，存一個模型檔或下載第二個資料集，都會讓第一個資料集的快取失效，下次執行就得重讀一遍。

`GraphInput` 搭配 `type=image` 在**畫布**執行時，用的是同一套機制：API 路徑已經把呼叫者的值放進 `params` 裡了，但畫布執行改成從磁碟載入 `default` 路徑——正是這個指紋，讓你在兩次畫布執行之間更換那張圖片時，能夠拿到新的像素。

### 從不快取的內容

有些節點仍然完全以 `cacheable = False` 退出快取，原因分四種：

**指紋無法描述的外部狀態。** `HuggingFaceDataset` 和 `KaggleDataset` 會碰網路，Kaggle 那個還會碰 `KAGGLE_*` 環境憑證——本機快取目錄的指紋沒辦法分辨「遠端版本變了」「憑證變了」跟「什麼都沒變」的差別，所以這兩個節點每次都會重新執行。`LLMChat` 因為要打遠端模型 API，也是同樣的道理。

**節點的目的本身就是一個副作用。** `ImageWriter`、`ModelSaver` 和 `CheckpointSaver` 存在的目的就是寫檔案；快取命中會直接回傳記錄下來的 `{"path": ...}` 而不去碰磁碟，但當節點的重點就是那次寫入時，這樣做是錯的（使用者刪掉輸出檔後重新執行，理應要能重建它）。不論上游餵給它們什麼，這幾個節點每次執行都會重新跑一次。

`TrainingLoop` 也在這一組，只是媒介不同、道理相同：它產出的不是它回傳的那個 `model` 把手，而是那個把手所指向的權重被改成什麼樣，加上每個 epoch 一筆的指標序列。這兩樣東西都無法從快取命中裡存活——所以不管餵給它的東西有沒有變，它每次執行都會重新跑。`EvaluateModel` 因為其中比較窄的那一半也在這裡：準確率確實在它的輸出裡，但它寫進準確率圖表的那個點不在，所以快取命中會讓一次被回報為成功的執行留下一張空圖。

**節點交回去的是一個活的、可變的物件。** `model`、`optimizer` 和學習率排程器，都是指向「訓練會就地改動的東西」的參考。快取鍵描述的是這種物件當初是怎麼**建出來的**——架構、超參數、上游的鍵——而從第一個 batch 跑起，它就不再描述這個物件了，於是重播記錄下來的把手，等於是把上一次執行已經訓練過的物件交給下一次執行。因此 `ModelLoader`、`CheckpointLoader`、`Inference`、`Optimizer`、`LRScheduler`、`DQN`、`PPO` 和 `RewardModel` 每次執行都會重新跑。

`ModelLoader` 和 `CheckpointLoader` 明明有一份好好的內容指紋，卻還是落在這一組，是因為指紋描述的是它們**讀**了什麼，而不是它們**寫**了什麼：`load_state_dict` 會寫進你接上去的那個 model，而快取命中跳過的正是這一步。代價比聽起來小——退出快取會往下游傳播（見下文），而只要它們的 `model` 輸入有接上，來源就是擁有權重的節點，那些節點本來就不可快取，所以在一般接法下，它們從來就沒被快取服務過。

**節點可能有副作用，而只有寫它的人知道。** `PythonScript` 執行的是你在畫布上打的程式碼。`code` 是會算進快取金鑰的參數，所以**改過**的腳本會重跑——但真正會命中快取的，是腳本沒改、輸入也沒變的那一次，而腳本可以就地改掉輸入的張量或模型、改動 `torch`／`numpy` 的行程級全域狀態，或使用 `ANY` 型別輸入連接埠交給它的任何東西。這些從節點的型別看不出來，從它的原始碼也檢查不出來，所以它無條件退出快取。參見[PythonScript 節點](../advanced/python-script-node.md#快取)。

同樣的退出機制，也涵蓋了輸出因其他原因逃出快取鍵範圍的節點——`GaussianNoise`、`DDPMSampler`、`BackwardOnce`、`DiffusionTrainingLoop`，以及每一個擁有權重的節點（`SequentialModel`、`DiffusionUNet`，還有每一個層節點：`Linear`、`Conv2d`、`LSTM` 等等），因為它們的參數會隨著訓練過程漂移。

對這些擁有權重的節點來說，第二次按 **執行** 要拿那些權重怎麼辦，是你的選擇而不是快取的選擇：**設定 → 訓練行為 → 在多次執行間保留權重**（預設開啟）會從上次執行結束的地方接續下去，而 **立即重置所有權重** 會把它們丟掉，讓下一次執行從全新的初始化開始。`SequentialModel` 每次執行都會在它的 **Log** 分頁說明這次是哪一種，所以 loss 曲線起點意外偏低時，永遠都有白紙黑字的解釋。

退出快取會**往下游傳播**：任何吃到這些節點輸出的節點也都會跟著重新執行，因為快取鍵只記錄上游節點的*鍵*，不記錄它們實際的輸出。否則，一個被快取住的下游節點就會拿著用舊資料算出來的過時結果交差。

### 預設組合（preset）與子圖方塊會回報什麼狀態

畫布上的 preset 節點和子圖實例，是一個方塊代表底下好幾個節點，所以它們只會回報一個狀態。回報哪一個，取決於裡面的節點實際做了什麼：

| 方塊顯示 | 意思 |
| --- | --- |
| `已完成` | 裡面至少有一個節點真的執行了。就算有一半是快取命中，仍然算有做事。 |
| `已快取` | 裡面**每一個**節點都是快取命中。這次什麼都沒跑，你看到的輸出是上一次執行留下來的。 |
| `已跳過` | 裡面每一個節點都因為上游有東西失敗而被略過。 |
| `錯誤` ／ `已中斷` | 裡面有節點失敗，或提早停止。這兩種都會立刻決定整個方塊的狀態。 |

其中最值得注意的是`已快取`：一個包著 `TrainingLoop` 的 preset 如果回報`已快取`，那這次**沒有訓練**。在這件事被區分開來以前，方塊兩種情況都寫`已完成`，所以「我改的東西到底有沒有讓它重跑」在 preset 這一層根本問不出答案。想讓它真的重跑，就改掉它依賴的東西，或是清掉快取。

## 可重現的執行（亂數種子）

預設情況下，執行時的亂數來自 PyTorch 自己挑的熵，所以同一張圖跑兩次，權重初始化會略有不同、洗牌順序會不同，loss 曲線也就跟著不同。在 **設定 → 訓練** 裡設定 **亂數種子**，就能讓一次執行可以重現。

設了種子之後：

- 每個節點都會用 `(種子, 節點 id)` 推導出來的值來設定種子，所以一個節點抽到什麼，只取決於種子和它自己的身分，不會受到圖中其他節點先消耗了多少亂數影響，也不會受到引擎排程順序影響。
- `DataLoader` 會拿到自己的 generator，所以每個 epoch 的洗牌順序也是固定的；每個 worker 行程也會拿到各自獨立的亂數串流。
- **執行時一次只跑一個節點，而且不會和其他執行重疊。** 設定種子寫的是整個行程共用的亂數狀態，所以不論是第二個節點、還是第二個「執行」，只要同時抽取亂數就會讓數字跑掉。因此設了種子的執行會先等目前進行中的執行結束，然後獨自執行；排在它後面送出的執行則會等它。沒有設種子的執行不受影響：彼此之間照樣平行，節點之間也照樣平行。

同一張圖、同一個種子跑兩次，在 CPU 上會得到位元完全相同的 loss 曲線；換一個種子就會得到真正不同的曲線。

「其他執行」指的是這台伺服器正在執行的每一張圖，包含以 `POST /api/graph/run/{name}` 直接呼叫的無介面執行：設了種子的執行進行時，它會等；而設了種子的執行也會等它。沒有設種子的無介面呼叫彼此之間照樣平行。

代價值得講清楚：設了種子的執行比較慢（在分支彼此獨立的圖上大約 3～4 倍，在一般偏線性的教學圖上幾乎沒有差別），而且即使是從畫布上啟動，也可能要等一個長時間的工作跑完。可重現性是選用功能，而一個要求可重現的執行寧可晚一點，也不要算錯。

**決定性演算法** 是另一半。它會要求 PyTorch 使用每次都以相同方式合併這些數值的運算核心（`torch.use_deterministic_algorithms(True, warn_only=True)`）。刻意採用 `warn_only`：沒有決定性實作的運算只會印出警告，而不會直接讓執行掛掉，所以你得到的是「所有能重現的部分都被重現了」，而不是一段來自 cuDNN 內部的錯誤堆疊。

種子會跟著這次執行一起被記錄下來，並顯示在 **執行紀錄** 面板中，所以任何一個有趣的結果都能追回到產生它的設定。

從命令列：

```bash
cdui run graph.json --seed 1234 --deterministic
```

:::note
種子固定的是「軟體層面」的亂數。位元完全一致的保證只適用於 CPU；換不同的 GPU、驅動程式版本或 PyTorch 版本時，浮點數的歸約順序仍然可能不同。
:::

## 停止

點擊 **停止** 可取消執行中的 run。**只有「停止」會取消 run。**

關閉瀏覽器分頁、切換到別的網址、或連線中斷都不會再停掉任何東西：run 活在伺服器上，不是活在連線裡。回來以後，分頁會重新連上原本在看的那個 run，把離開期間錯過的訊息全部補播到結果面板，然後繼續即時追蹤 — 所以長時間的訓練可以撐過重新整理、闔上筆電、或不穩的 Wi-Fi。

取消是「合作式」而非立即生效，因為沒有安全的方式從中間打斷任意的節點程式碼。長時間執行的節點每個 batch／step／item 都會檢查一次 — 訓練迴圈會在一個 batch 之內停下來，並在離開前寫下中斷用的 checkpoint — 其餘節點則會把當次呼叫做完，之後 run 在下一個節點邊界停止。兩種情況都會記錄成 `cancelled`。

## 瀏覽器之外

你可以從命令列執行任何已儲存的圖，而不需要啟動伺服器 — 見 **[CLI 圖形執行器](./cli-runner)**。
