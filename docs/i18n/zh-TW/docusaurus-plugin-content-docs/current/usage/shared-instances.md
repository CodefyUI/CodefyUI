# 共用的伺服器

CodefyUI 是一個剛好用 HTTP 溝通的桌面工具。下面講的每一件事，對「自己筆電上自己用」的安裝來說都完全正確而且不奇怪 -- 環境層級的憑證本來就該是環境層級的。但當這台機器別人也連得上，同樣的行為意義就不一樣了，這一頁就是在講不一樣在哪裡。

如果你還沒讀過[發佈](./publish)，請先讀；那一頁的第 6 節講的是綁定區域網路會暴露什麼。這一頁是同一個故事的憑證那一半。

## 一台伺服器只有一個身分

這裡沒有使用者帳號。工作階段權杖（session token）只能證明「這個請求來自一個讀得到本機某個檔案的東西」，證明不了**是誰**送的。所以伺服器持有的每一份憑證，都是以整台伺服器的名義持有，而不是以「現在開著瀏覽器分頁的那個人」的名義。

**在共用的機器上，設定憑證的人替所有人付錢，而且沒有任何紀錄說得出錢是誰花的。**

有三種憑證是這樣運作的。

### ChatGPT 登入

`POST /api/llm/codex/login` 走完 OAuth 流程後，會把存取權杖與更新權杖寫進使用者資料目錄底下的 `codex_auth.json`（Windows 是 `%LOCALAPPDATA%\codefyui\llm\`，Linux 是 `~/.local/share/codefyui/llm/`，macOS 是 `~/Library/Application Support/codefyui/llm/`）。在有意義的平台上這個檔案是 chmod 0600 -- Windows 上沒有意義，那裡靠的是資料夾本身的帳號權限。

代理層只檢查「有人登入了」，不檢查「登入的是不是你」：

- 只要有一個人登入，這台伺服器上**每一張**用 ChatGPT 供應商的圖，帳都算在那個人的個人 ChatGPT 帳號上。
- `POST /api/llm/codex/logout` 除了工作階段權杖以外不需要任何參數。任何連得上編輯器的人都可以把你登出。

### 來自環境變數的 LLM API 金鑰

當 `LLMChat` 節點的金鑰參數是空的，節點會依序退回去讀行程的環境變數：

- OpenAI：先 `CODEFYUI_OPENAI_API_KEY`，再 `OPENAI_API_KEY`
- Anthropic：先 `CODEFYUI_ANTHROPIC_API_KEY`，再 `ANTHROPIC_API_KEY`

`cdui` 啟動時會從專案的 `.env` 載入這些變數，所以放在那個檔案裡的金鑰，等於是這台伺服器上每一張圖都花得到的金鑰。這個退回機制刻意是安靜的 -- 一張金鑰參數留空的圖，不會告訴你它用了伺服器的金鑰。**請假設任何人跑得動的圖，都花得到你們公司的 LLM 預算。**

有一件事這個退回機制刻意**不**做：`custom` 供應商永遠拿不到金鑰，所以一張把 `base_url` 指向攻擊者的圖，沒辦法把你的金鑰帶出這台機器。

### Kaggle

`KaggleDataset` 節點使用 `KAGGLE_USERNAME` 加 `KAGGLE_KEY`，或者是這個服務帳號的 `~/.kaggle/kaggle.json`。下載會算在那個 Kaggle 帳號頭上，包括你以那個帳號同意過的競賽規則。

## 那什麼才是每張圖各自的

型別標示為 SECRET 的參數 -- 例如 `LLMChat` 節點的 `openai_api_key` -- 屬於打字的那個人，處理方式不一樣。伺服器寫出去的每一份副本都會把它清空：存檔的圖、匯出的檔案、發佈的應用程式版本、預設組合（preset）、產生的 Python 程式碼，以及執行紀錄。

有兩個後果值得講清楚：

- SECRET 參數**不會**被存在任何地方。重新載入編輯器、重新匯入一個匯出的圖、或是在重開過的伺服器上把排隊中的執行推上去跑，這個欄位都會是空的，節點會用它原本的「需要 api key」錯誤失敗。這是刻意的取捨，不是 bug。
- **如果你在「執行紀錄清除機制」進來之前跑過含有 SECRET 參數的圖，請把那把金鑰視為已外洩並更換掉。** 舊版本會把執行時的圖原封不動寫進 `exec_runs.graph_snapshot` 欄位，而執行紀錄是依**數量**保留（最新的 200 筆），不是依時間 -- 所以在一台不常用的機器上，那個值永遠不會被擠掉。升級後下一次啟動會把這些值從資料列裡掃掉，並記錄清掉了幾筆。它**不會**覆寫掉原本的位元組：SQLite 把舊的頁面丟回自己的空閒清單時並不會歸零，所以一份副本可能會留在資料庫檔案和它的 `-wal` 附屬檔裡，直到執行 `VACUUM` 為止。更換金鑰才是真正的解法；這個清除只能讓它讀不回來。這項變更收在哪一個版本，請看 CHANGELOG。

## 如果你需要分辨是誰用的

目前產品本身沒有答案。請一個人開一台，讓每個人提供自己的憑證 -- 各自的 `.env`、各自的 `CODEFYUI_USER_DATA_DIR`、各自的連接埠。除此之外的做法都是共用同一個身分，而且從編輯器裡面看不出來正在共用。
