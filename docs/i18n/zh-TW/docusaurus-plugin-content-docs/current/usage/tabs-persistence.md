# 分頁與持久化

## 多分頁工作區

CodefyUI 支援以分頁形式呈現多個獨立的畫布。每個分頁都有各自的：

- 節點、連線與排版
- 執行環境與紀錄
- 錄製的輸出與保留的權重（見[教學檢視器](./teaching-inspector)）
- 復原／重做歷史（最多 50 步）

你可以並列保留多個實驗，例如在一個分頁放訓練 graph，另一個放推論 graph，而且各分頁的狀態不會互相干擾。

### 分頁列 {/* #the-tab-strip */}

雙擊分頁可重新命名（`Enter` 套用，`Esc` 取消）。正在執行的分頁會在名稱旁顯示一個圓點。**唯讀**徽章表示儲存（以及外掛寫入）會被拒絕，通常是因為該 graph 由比目前更新的 CodefyUI 寫入；重新命名與關閉仍然可用。外掛開啟的分頁則會在游標停留時說明來源。關閉含有 graph 的分頁前，系統會先確認並指出節點數量，因為關閉分頁無法復原。伺服器從[專案目錄](./project-directories)執行時，每個專案會保留自己的一組分頁。

## 自動儲存

所有分頁都會自動存在瀏覽器裡，因此重新載入頁面時你的工作會被還原。這是瀏覽器本機的儲存；不會同步到伺服器。所以換一個瀏覽器或另一台電腦時，這些分頁都不會出現；要把它們帶過去，請用[工作區檔案](#workspace-files)。

儲存使用 **IndexedDB**，每個分頁各存一筆資料。這對大型 graph 很重要：舊的 `localStorage` backend 對每個來源大約只有 5MB 上限，graph 一旦超過就會直接停止儲存。IndexedDB 沒有相當的實務上限，而且每次只有目前編輯的分頁會重新寫入。

第一次開啟採用 IndexedDB 儲存的版本時，`localStorage` 最後儲存的內容會自動複製到 IndexedDB，不需要任何操作。舊的 `localStorage` 副本會保留（所以降回舊版仍可開啟它最後讀取的 graph），但之後不再更新。

如果你的瀏覽器沒有可用的 IndexedDB — 某些無痕模式，或被 sandbox 限制的 iframe — 儲存會退回 `localStorage`，也就回到它原本的容量上限與「儲存空間已滿」的警告。

## 儲存與載入 {/* #saving-and-loading */}

已儲存的 graph 放在伺服器上，而不是瀏覽器中：

- **檔案 → 儲存**與工具列的**儲存**圖示，會把目前分頁的 graph 直接寫回它開啟時的那個 graph，不會再詢問。伺服器跑在哪裡都一樣，這件事不需要專案目錄。還沒綁定任何 graph 的分頁（新畫布、匯入的檔案、插入的範例）以及**另存新檔...**則會詢問名稱，並在這個名稱會蓋掉清單裡既有的 graph 時先提醒。**檔案 → 清除畫布**會在確認後清空分頁。
- 側邊欄的**圖表**分頁會列出這些 graph（可搜尋，最近修改的排在前面），並標出目前分頁綁定的那一列。點擊一列會用新分頁開啟那個 graph，並把分頁綁定到該檔案。你正在編輯的畫布不會被取代，所以沒有東西要確認，也不會弄丟東西。點擊已經開著的 graph 則會切到持有它的分頁，而不是再開一份。
- 該列的選單只有兩個項目：**重新命名**與**刪除**。刪除會先確認，再把檔案從磁碟移除，在[專案目錄](./project-directories)下則會連同它的另一半一起刪除。被更名或刪除的檔案正好是某個分頁要存回去的那一個時，該分頁會跟著改：綁定到新名稱，或不再綁定任何檔案，讓下一次儲存改為詢問，而不是把你剛刪掉的檔案默默寫回去。面板的標題列也有自己的**另存新檔...**，讓一次儲存直接出現在你正在看的清單裡。

## 匯入／匯出

你可以把任何 graph 匯出成 JSON 檔案，之後再匯入回來（或分享）：

- **匯出 → 匯出為 JSON**會把目前分頁的 graph（節點、連線、參數、段落標記與子圖定義）寫成一個 `.json` 檔案。
- 側邊欄**圖表**分頁底部的**匯入...**可以讀取 graph 的 `.json`，也可以讀取[工作區檔案](#workspace-files)，並依檔案內容（而不是檔名）分辨兩者。兩者的結果相反：匯入 graph 會**取代**目前分頁的畫布，若要保留現有 graph 請先開一個新分頁；匯入工作區檔案只會**增加**分頁，不會動到任何已開啟的分頁。不是 graph 的 `.json` 檔會被拒絕並顯示訊息，不會把畫布清空；由較新版 CodefyUI 寫出的 graph 則會以唯讀方式開啟，並顯示通知。匯入的 graph 不綁定任何檔案，所以第一次儲存會詢問名稱。
- **匯出 → 匯出架構圖 (SVG)／匯出架構圖 (PNG)**只會繪製架構 — 節點、連接埠與連線，不含參數值 — 並使用適合文件的淺色背景。
- **匯出 → 匯出為 Python**會產生一個可讀的單檔 Python 程式：每個節點一個函式（參數以可編輯的字面值內嵌）、依執行順序把節點串接起來的流程函式，以及帶有簡易命令列介面的 `main()` 進入點。每個節點函式都委派給畫布所使用的同一份節點實作，因此執行結果與畫布一致。請用相容的 CodefyUI 安裝環境中的 Python 來執行；不需要啟動網頁伺服器。用 `--help` 查看裝置、GraphInput JSON、逾時與專案資產等選項。

後端的範例 graph 使用的正是同一種 JSON 格式，所以匯出的 graph 也可以用 **[CLI 圖形執行器](./cli-runner)**在無介面（headless）下執行。

:::tip
因為 graph 是純 JSON，所以可以直接進行 diff 與版本控制。將 graph 與程式碼一起 commit，即可記錄一個精確且可重現的管線版本。
:::

### 工作區檔案 {/* #workspace-files */}

**匯出 → 工作區 (.cduiworkspace)**會把所有開啟的分頁寫進一個檔案 `workspace-YYYY-MM-DD.cduiworkspace`，讓整個工作階段可以搬到另一個瀏覽器或另一台電腦。**匯入...**可以把它讀回來：分頁會加在現有分頁旁邊，不會取代任何已開啟的 graph；如果瀏覽器裡只有一個空分頁，匯入後就只會留下匯出的那一組分頁。

檔案會記下每個分頁的標題、graph 與執行設定：亂數種子、決定性演算法、錄製節點輸出、顯示內部步驟、在多次執行間保留權重、擷取梯度與自動合成損失。也會記下當時作用中的分頁，以及六項偏好設定：語言、字級、連線樣式、對齊格線、顯示節點說明與節點分類模式。檔案裡的每個 `tabs[i].graph` 都是一般的「匯出為 JSON」graph。

以下內容不會寫進檔案：

- 機密參數值
- 外掛存在瀏覽器裡的資料，例如助理外掛存放的 provider API 金鑰
- 執行結果與訓練出的權重：它們放在伺服器的記憶體裡
- 分頁與已儲存 graph 之間的綁定
- 設定裡的運算裝置與面板版面：它們只屬於這一台電腦

因此匯入的分頁不綁定任何已儲存的 graph：第一次儲存會詢問名稱，而且在蓋掉清單裡既有的名稱之前會先確認。在[專案目錄](./project-directories)下，也要等到第一次儲存才會標記。

機密值是依節點定義認出來的，所以負責匯出的那個瀏覽器若沒有載入某個節點類型（外掛被停用或沒安裝），就認不出它的機密值；儲存與**匯出為 JSON**也有同樣的限制，分享檔案前請先檢查這類分頁。

空分頁、唯讀分頁與外掛暫時開啟的分頁不會被匯出。匯入時，不是 graph 的項目，或會成為第 33 個分頁的項目會被略過，其餘照常開啟 — 一次匯入最多開到 32 個分頁，而匯入時被取代的那個空分頁不算在內。超過 64 MiB 的檔案，或由較新版 CodefyUI 寫出的工作區檔案，會整個被拒絕。這裡沒有安裝的節點類型會以佔位節點開啟，並以警告列出缺少的類型；之後不會自動修復，請先安裝它所屬的外掛或自訂節點，再重新匯入檔案。
